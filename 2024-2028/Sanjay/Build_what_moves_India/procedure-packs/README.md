# Procedure packs

`packs/` contains versioned JSON procedure data and `schemas/` contains the generated Procedure Pack v1 JSON Schema. Packs are validated by `sahayi_api.procedures`; API and frontend code must not hard-code procedure facts. The active packs cover UIDAI Aadhaar address update and Kerala Indira Gandhi National Old Age Pension preliminary readiness guidance.

Active packs carry an exact `en`/`hi`/`ml` locale contract. Existing English fields are canonical; `localization.translations` contains complete Hindi and Malayalam citizen-facing text while stable IDs, rules, option values, amounts, URLs, provenance, and source dates remain language-neutral. Locale metadata records English as `canonical_source`/`canonical_verified` and both translations as `machine_assisted_prototype`/`native_review_required`. Validation rejects missing or extra translated keys and any other locale. No runtime translation service is used. Linked official source wording prevails, and prototype translations require native-speaker and legal review before production use.

The 2026-08-28 translation-source recheck included the packs' canonical UIDAI and Kerala government URLs, UIDAI's official [Hindi Enrolment & Update route](https://uidai.gov.in/hi/enrolment-and-update) and [Hindi fee PDF](https://www.uidai.gov.in/images/Aadhaar_Enrolment__and__Update__-__Hindi.pdf), Kerala's [Sevana criteria](https://welfarepension.lsgkerala.gov.in/FAQsEng.aspx?pentypeid=2), and its [LSG old-age-pension page](https://lsgkerala.gov.in/en/welfarepension/iop). The recheck did not locate complete official Hindi and Malayalam equivalents for every citizen-facing field in both procedures, so only the previously validated English content was translated; no new facts, resolved amounts, third-party policy translation, or substituted official URL was introduced.

Fee facts use an explicit verification status. Confirmed and free values require sourced agreeing claims; conflicting values retain every sourced claim without a canonical amount and include official-confirmation guidance; not-stated fees do not invent an amount. Fee conflict does not replace the independent pack freshness state.

Guided journey behavior is represented by the required `readiness` section in the current contract. It contains localized structured questions, additional official-review items, outcomes, and prioritised rules. Questions accept only booleans, enumerated single choices, or bounded integers; free text and citizen identifiers are outside the contract. Pack-labelled sensitive choices must be categories, display a frontend privacy explanation, and offer an explicit withheld choice where needed. Additional-review items keep subjective or intrusive official criteria out of automated inference. Conditional visibility and rules use only the strict JSON AST operators `all`, `any`, `not`, `known`, `equals`, `in`, `lt`, `lte`, `gt`, and `gte`.

Active packs carry strict `assistance.preparation_fields` metadata. It defines the localized worksheet title/mode and, for every bounded field, stable field/question IDs, complete localized label/question/why text, input and local-validation types, required/sheet/confirmation/edit behavior, allowed value sources, reviewed source IDs, and optional readiness-question or document-clue mappings. Handling remains `fictional_demo`, `citizen_private`, or `not_collected`; separate bundled personas are marked `synthetic:true`. Validation requires known/unique fields, questions, sources and document IDs, valid option/input combinations, no demo value on private fields, and a PDF source for every official-form worksheet. UIDAI 1.5.0 declares a Sahayi preparation worksheet because no applicable official fillable form was established. Kerala 1.3.0 maps only field families verified from the official IGNOAPS PDF. The graph receives only completed field IDs; citizen values are validated, stored, edited, and printed in browser memory. The model cannot author or override fields or values.

An active referenced source may declare a strict `monitoring` policy with expected HTML/PDF format, normalization version, exact HTTPS source URL, bounded size, optional approved DNS redirect aliases, and bounded reviewed fingerprint metadata. A reviewed baseline requires digest, timestamp, normalized/raw size, and content type together; optional ETag/Last-Modified values are bounded single-line review aids. Empty baseline fields mean `review_required`, not that monitoring already happened. Configuration on an unreferenced source is rejected. Monitoring metadata never changes procedure facts, provenance, conflict resolution, or lifecycle state.

Pack validation rejects unknown fields/operators/references, duplicate IDs/priorities, incompatible operator and answer types, invalid choices, missing or unsafe defaults, and expressions beyond configured depth, node, and list budgets. Evaluation applies an independent operation budget. Every question, rule, and outcome cites pack sources, and every outcome includes an official HTTPS handoff plus explicit wording that readiness guidance is not an eligibility decision or official approval.

Run `.venv/bin/python -m sahayi_api.procedure_tool validate` to validate the active registry and `.venv/bin/python -m sahayi_api.procedure_tool check-schema` to detect schema drift. Run `.venv/bin/python -m sahayi_api.procedure_tool monitor` for the tracked offline demo. `--json` selects structured output and `--output PATH` is the only way to create a report file. Explicit live mode requires both `--live` and `--acknowledge-live-public-source-check`; it is one-shot review support, never a hosted/admin endpoint, automatic pack updater, conflict resolver, or continuous monitor.
