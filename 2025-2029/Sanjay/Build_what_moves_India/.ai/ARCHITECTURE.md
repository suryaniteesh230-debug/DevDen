# Architecture

The default release journey is one minimal React conversation surface. Start loads the narrow catalogue; raw natural-language input passes the existing local PII gate and multilingual phrase/Naive Bayes ensemble without a request. The browser sends candidate service IDs, then confirmation, to strict `POST /api/v1/conversation/turn`. One compiled typed LangGraph runs safety/consent, intent clarification, verified-procedure routing, confirmed document evidence, deterministic interview/readiness, parallel checklist/preparation, explanation, and pack-owned official handoff nodes. The 12-step graph has at most one optional provider call and no checkpointer, store, Agent Server, durable interrupt, server thread, database, LangSmith tracing, or telemetry. Browser-carried state is untrusted and revalidated/recomputed against the active Procedure Pack every turn.

The graph adds no factual or generative authority. Its explicit actions are route/clarify, ask the current pack readiness or preparation question, validate structural completion IDs, evaluate, prepare, and hand off. Strict pack `preparation_fields` define stable field/question IDs, localized labels/prompts, input and local-validation types, reviewed sources, allowed local value sources, confirmation/edit/sheet behavior, and readiness/document mappings. Personal values and OCR suggestions never enter graph state. Inside a Kerala pension task, a narrow multilingual address gate mirrors the server catalogue gate: an unqualified address change offers only the loaded Aadhaar/pension catalogue entries, while an explicit pension-record request fails closed because no separate verified procedure exists. Aadhaar name change and other known out-of-scope requests fail closed locally. Provider availability is irrelevant to this deterministic path.

Optional document assistance lazy-loads pinned Tesseract.js/PDF.js after explicit action. JPEG/PNG/WebP/PDF require MIME/signature agreement; limits are 10 MiB, 20 megapixels per image/page, three PDF pages, one job, 30 seconds per page, and 75 seconds total. Worker/core/English/Hindi/Malayalam data are checksum-verified and same-origin. Raw files, filenames, OCR text, identifier-shaped values, canvases, and worker state remain ephemeral in the browser; only a citizen-confirmed allowlisted document ID plus booleans may reach the graph. Local OCR is uncertain preparation assistance, never document authenticity or government validation.

Optional voice is a dependency-free browser enhancement. SpeechRecognition/webkitSpeechRecognition is explicit-start only and selects `en-IN`, `hi-IN`, or `ml-IN`; recognition may use browser/vendor processing and is not represented as on-device. Transcripts stay in memory, pass through the existing identifier gate, and are never logged or persisted. Speech synthesis reads current visible deterministic content using an appropriate available locale voice. Recognition and synthesis are cancelled on navigation, locale change, unmount, Start Over, End Session, and inactivity expiry; full text/touch use remains available.

The offline-first source monitor may also be invoked by a daily read-only GitHub Actions workflow. It uses exact pack allowlists, no secrets or citizen information, uploads bounded review metadata, and fails visibly for changed, error, and missing-baseline states. It never edits or activates Procedure Packs, mutates the repository, promotes a branch, or deploys Render; current missing baselines correctly require human review.

The optional assistant now has a narrow deterministic catalogue gate before provider invocation. Explicit matches to a different active Procedure Pack offer a switch using only loaded registry service IDs. An unqualified address-change request inside the Kerala pension journey distinguishes Aadhaar address update from pension-record-related help and states that the catalogue has no separate verified pension-record address-change procedure. Fail-closed paths log only bounded operational reason metadata (configuration category, provider/model, HTTP status, exception class, response status, round, and tool-call count), never prompts, outputs, tool arguments/results, client addresses, credentials, exception messages, or stack traces. The frontend renders the latest structured assistant response once while retaining only its bounded in-memory transcript.

The implemented frontend is React/TypeScript/Vite; the backend is FastAPI. Development uses loopback Vite and API servers. A production build is served by FastAPI so the browser uses same-origin API paths.

Local kiosk mode and a future hosted web-demo mode share this application shape. React fetches `/api/v1/health`, `/api/v1/public-config`, and the read-only `/api/v1/procedures` catalogue/detail resources. It posts a complete bounded answer map to the stateless procedure readiness endpoint after each readiness choice. FastAPI returns JSON with no-store headers. No identifiers, free text, documents, or exact financial details are collected or stored; structured readiness answers exist only in React memory and the current request. A pack may label a closed-choice question as sensitive, which triggers a privacy explanation and an explicit non-forced withheld choice in the UI; this is metadata, not persistence.

The initial service finder is a separate browser-only boundary. The client receives a deliberately narrow active-pack catalogue localized to exactly `en`, `hi`, or `ml`. Obvious Aadhaar-like numbers, Indian phone-like numbers, email patterns, and numbered addresses are blocked before intent work. The browser then runs both the existing deterministic pack-phrase scorer and a statically bundled character 2–5-gram Multinomial Naive Bayes classifier trained offline on owned synthetic English/Hindi/Malayalam examples. NFKC/lowercase/letter-number normalization is shared with the standard-library trainer. Confidence and top-two margin thresholds are tuned on validation only; labels map through a two-service allowlist and unsupported maps to no service. Agreement, one-sided confidence, disagreement, unsupported, and dual abstention follow a strict confirmation-first ensemble. Invalid artifacts silently disable ML. No browser LLM, inference runtime, WebGPU/WASM, model download, generation, fact/eligibility decision, or network request is involved.

The raw finder query and inference result never enter a URL, request, log, analytics event, cookie, browser storage, or backend call. They are cleared after confirmation, language change, Start Over, End session, and inactivity expiry. Native-script phrases coexist with English/transliterated spellings. The identifier detector remains a warning aid, not a guarantee that every personal detail is detected. Every proposed match requires citizen confirmation, and an ambiguous choice receives confirmation before opening a service.

Procedure facts cross one deterministic boundary: JSON files under `procedure-packs/packs/` are validated by strict Pydantic Procedure Pack v1 models, checked for version/lifecycle/provenance/localization consistency, assigned a canonical SHA-256 digest, and loaded into an active read-only registry. English remains the canonical fact text and default API locale. Active packs must supply every derived citizen-facing key for Hindi and Malayalam; metadata marks those machine-assisted prototype translations as requiring native review. Stable facts, IDs, rule expressions, option values, sources, URLs, retrieval dates, and provenance are shared across locales. Locale selects text only, so identical answer maps resolve the same outcome. No runtime translation service or third-party resource is called. Draft and superseded packs are excluded; multiple active versions, invalid packs, missing translations, or no active packs fail closed. Freshness is computed at response time from `review_due_at`, so expired guidance is returned as stale rather than current. Conflicting official fee claims remain structured, source-linked facts with no canonical amount; a derived attention flag exposes that conflict independently of freshness.

The React UI uses a dependency-free typed message catalogue for its own `en`/`hi`/`ml` strings and pack/API text for procedure content. Locale and all citizen workflow state remain in component memory; changing language refetches the current deterministic representation, updates the document `lang`, and never changes rules or persists a preference. System Indic fonts are used, with no runtime font download. English is disclosed as canonical, linked official source wording prevails, and Hindi/Malayalam are not represented as certified translations.

The readiness engine evaluates only a validated JSON AST with the operators `all`, `any`, `not`, `known`, `equals`, `in`, `lt`, `lte`, `gt`, and `gte`. Pack loading enforces references, answer/operator compatibility, a single safe default, and depth/node/list budgets; request evaluation has a separate operation budget and strict answer validation. Packs can also carry source-cited additional-review items for conditions that must be respectfully handled by an official local body rather than inferred from a kiosk answer. Identical pack digests and answer maps produce identical responses. Responses expose stable question/rule/outcome IDs and official source records, never citizen answers or internal paths. “Readiness” always means personalised procedural guidance, not an eligibility decision or official approval.

Future boundaries include a broader privacy gateway if citizen-input features are ever approved. Cryptographic signing is deliberately deferred; the current digest provides traceability, not authenticity. Durable data is limited to verified source packs and build artifacts; workflow state is ephemeral. See [architecture](../docs/architecture.md) and the [privacy boundary](../docs/privacy-boundary.md) for details.

The optional agent boundary is `POST /api/v1/assistant/turn`. It accepts only locale, one bounded message, up to four bounded identifier-screened prior messages, an allowlisted service ID, closed-choice readiness answers, and affirmative consent. Browser and backend gates reject common address/email/phone/Aadhaar shapes, including ASCII, Devanagari, and Malayalam digits, without echoing rejected text. Conversation, consent, checklist, worksheet, and readiness state live only in React memory and are cleared by language change or Start Over. Public config exposes `agent_available` plus the fixed provider/model; the key, model limits, provider errors, prompts, raw output, and tool arguments never cross the server boundary.

The server owns a small Groq provider adapter around the OpenAI-compatible Chat Completions endpoint at fixed `https://api.groq.com/openai/v1` and sole allowlisted `openai/gpt-oss-120b`. The `openai/` prefix is Groq's model namespace, not an OpenAI provider switch; the only provider credential is the server-side `GROQ_API_KEY`. It uses no SDK retry, automatic model substitute, optional reasoning/provider-specific parameters, built-in browser search, code execution, MCP/remote tools, or arbitrary functions. It retains a short timeout, bounded output/tool rounds, a process request budget, global semaphore, and a stale-cleaned per-client limiter keyed by an ephemeral salted hash. The bounded system/history/current-user messages never include preparation values, OCR content, documents, or identifiers. Canonical strict local schemas and Pydantic validation remain authoritative and unchanged. Provider routing exposes only the current application-selected phase: one catalogue tool for safety/intent; catalogue plus verified procedure for routing; readiness questions plus evaluation for interview; checklist plus synthetic preparation for automatic preparation; one simulated-status tool for explanation; and no tool for official handoff. Every provider function has a zero-argument object schema with no union, nullable type, nested answer array, or `maxItems`; validated locale, confirmed service, readiness answers, synthetic persona, and demo status are bound into the canonical executor locally. No request exposes more than two tools. Tool-call IDs, node-allowlisted names, empty JSON arguments, canonical bound arguments, and local results are validated; only reconstructed allowlisted assistant tool-call fields and the matching documented tool-result message continue the loop. The first request uses automatic tool choice with parallel calls disabled; after a tool result, the final request removes tools and sets `tool_choice="none"`. Because Sahayi does not combine tool use with Structured Outputs, the final JSON-only instruction is enforced with strict Pydantic validation rather than a provider response schema. The seven registered deterministic tools remain `list_supported_services`, `get_verified_procedure`, `get_readiness_questions`, `evaluate_readiness`, `build_personalized_checklist`, `prepare_synthetic_form_assistance`, and `explain_simulated_status`. LangGraph and all tools remain application-controlled. Model prose may guide, but factual cards, actions, fees, sources, outcomes, checklists, worksheets, demo status facts, and official handoff destinations are reconstructed locally. Provider failure returns deterministic Sahayi guidance; arbitrary model IDs, URLs, actions, and unsupported approval/fee/status claims fail closed. Greetings and obvious low-information input are answered locally before provider access. Provider failures are logged only as allowlisted categories, status/class metadata, graph node, fixed exposed-tool names/count, bounded round/tool counts, and whether failed-generation metadata exists; its contents, prompts, citizen text, tool arguments/results, response bodies, exception messages, client addresses, and credentials are excluded.

Checklist generation is deterministic for both services and all locales and refreshes with every primary interview turn. Pack metadata defines bounded localized preparation fields, source references, handling state, local validation, and separate fictional personas. React overlays confirmed local answers, derived readiness labels, and confirmed OCR clue values on the structural sheet; only completed field IDs cross the API. Kerala labels remain limited to fields verified from the official IGNOAPS PDF; Aadhaar is explicitly a Sahayi preparation sheet because no applicable official fillable form was established. Unsupported/identifier fields remain blank and browser printing is the only save flow.

Procedure Intelligence is a separate administrative boundary. Active source records may declare expected HTML/PDF format, deterministic normalization, size and redirect bounds, and bounded reviewed metadata. The offline-first CLI compares a reviewed fingerprint with one candidate and emits only bounded review metadata. Live retrieval is absent from hosted routes and requires an explicit CLI flag plus acknowledgement; it uses exact HTTPS pack URLs, declared DNS aliases, manual bounded redirects, no credentials/cookies/retries/JavaScript, and accepted HTML/PDF types only. Detection never edits facts, resolves conflicts, changes lifecycle state, or publishes a pack. Missing baselines and changed content require human review while the last reviewed pack remains active.

Demo submission/status is strict, stateless, and fully synthetic. Both services expose normal and action-required sequences built from an allowlisted persona, scenario, status enum, and an obviously synthetic `DEMO-...` reference. Advancing is deliberate; no government or undocumented endpoint is contacted and no official outcome is implied. The frontend retains the response in memory only.

Every citizen screen has an End session control. It aborts tracked fetches, invalidates late responses, clears query, selection, answers, consent, conversation, checklist, worksheet, demo and navigation state, revokes any tracked object URLs, and returns to the localized welcome. A bounded public timeout configuration drives elapsed-time inactivity warning and the same clearing operation; visibility restoration recomputes elapsed time. No cookie, browser storage, service worker, analytics, telemetry, or durable server session is used. The confirmation accurately covers Sahayi memory only, not browser/network/provider retention outside Sahayi.
